## 1. 이 문서의 역할

`project-direction.md`가 "무엇을 만들 것인가"를 정리한 문서라면, 이 문서는 "실제로 어떤 버전에서 무엇이 구현됐는가"를 기록하는 문서다.

쉽게 말하면 다음처럼 나뉜다.

```text
project-direction.md
-> 제품 의도, 기능 범위, 구현 원칙

project-after-direction.md
-> 현재 구현 상태, 버전별 패치, 실제 파일 구조, 유지보수 기준
```

이 문서는 단순한 changelog가 아니다. 버전마다 어떤 기능이 들어갔고, 그 변경이 제품 방향과 어떻게 연결되는지 같이 기록한다.

## 2. 현재 구현 요약

현재 빌드는 `치지직 채팅 커스텀`이라는 이름으로 동작한다.

사용자는 확장 팝업에서 채팅 미리보기를 보면서 표시 항목, 글자 크기, 색상, 자동 대비 보정, 채팅창 모드, 빠른 버튼 표시 여부를 조정할 수 있다. 설정은 저장되고, 치지직 페이지의 content script가 이를 읽어 사용자의 브라우저 화면에만 반영한다.

현재 사용자에게 보이는 핵심 기능은 다음이다.

- 닉네임, 배지, 타임스탬프 표시 토글
- 채팅 외 패널 표시 토글
- 채팅 박스 색상
- 글씨 크기와 닉네임 크기 조정
- 굵게
- 글자 색상 변경
- 닉네임 색상으로 채팅 표시
- 글자색 자동 보정
- 나만 보는 채팅창과 로컬 메시지 표시
- 미니 플로팅 채팅창
- 채팅 헤더의 설정·미니 채팅 버튼과 하단 전송 영역의 나만 보기 버튼
- 스타일 프리셋과 나만의 프리셋 저장

현재 확장이 하지 않는 일도 명확하다.

- 실제 채팅 메시지를 바꾸지 않는다.
- 치지직 서버로 채팅 전송을 대신하지 않는다.
- 삭제, 차단, 신고, moderation 기능을 제공하지 않는다.
- 치지직 서버 상태나 방송 송출에 영향을 주지 않는다.

## 3. 프로젝트 디렉션 반영 맵

| 프로젝트 디렉션 항목 | 현재 구현 상태 | 실제 표현 방식 | 주요 파일 |
|---|---|---|---|
| 로컬 표시 제어 | 완료 | `storage`에 저장된 옵션을 content script가 페이지에 적용 | `background.js`, `content-options.js`, `content-runtime.js` |
| 닉네임/배지/시간 토글 | 완료 | 채팅 행을 분석해 각 요소 표시를 독립 제어 | `content-chat-annotate.js`, `content.css`, `popup.html` |
| 채팅 외 패널 숨김 | 완료 | 랭킹, 승부예측 등 비채팅 패널을 옵션으로 숨김 | `content-core.js`, `content.css`, `popup.js` |
| 채팅 박스/글자 스타일 | 완료 | CSS 변수와 dataset으로 색상, 크기, 굵기 적용 | `content-core.js`, `content-theme.js`, `content.css` |
| 글자색 자동 보정 | 완료 | 사용자가 자동 보정을 켠 경우에만 대비 보정 적용 | `content-chat-annotate.js`, `content-options.js`, `popup.js` |
| 나만 보는 채팅창 | 완료 | credentialless guest iframe의 원래 채팅 외형을 유지하고, 입력은 전송 경로와 분리해 같은 채팅 목록의 로컬 행으로만 추가 | `content-guest-chat.js`, `content.css` |
| 미니 플로팅 채팅창 | 완료 | 드래그, 리사이즈, 입력 전용, 전체화면 전용, 최소화 지원 | `content-mini-chat.js`, `content.css` |
| 빠른 버튼 | 완료 | 설정·미니 채팅은 헤더에, 나만 보기는 하단 전송 버튼 왼쪽에 표시 | `content-guest-chat.js`, `content.css`, `popup.html` |
| 미리보기 중심 팝업 | 완료 | 팝업 첫 화면에 채팅 미리보기와 프리셋 배치 | `popup.html`, `popup.css`, `popup.js` |
| 버전 동기화 | 완료 | manifest/package/popup/content-bootstrap 버전 동기화 | `manifest.json`, `package.json`, `package-lock.json`, `popup.js`, `content-bootstrap.js` |

## 4. 버전별 패치 기록

  - 확장 권한을 심사 친화적으로 축소

기술 변경:

- `content.css` 분리
- 기존 큰 `content.js` 구조 정리 준비
- package/validator 구조 대폭 정리
- `activeTab`, `scripting`, `webNavigation` 권한 제거

권한 변경 배경:

초기 버전에서는 실제 치지직 페이지와 subframe 대응, stale content script 재주입, navigation 대응을 위해 권한이 점점 늘어났다.

- `0.1.0`: `storage`, `activeTab`
- `0.1.1`: `scripting` 추가
- `0.1.14`: `webNavigation` 추가
- subframe 대응 과정에서 `https://*.chzzk.naver.com/*` host permission 사용

하지만 스토어 심사 관점에서는 권한이 많을수록 심사가 늦어지거나 설명 부담이 커질 수 있다. `0.4.1`에서는 이 문제를 줄이기 위해 직접 주입과 navigation 재주입 흐름을 제거하고, manifest content script 중심으로 단순화했다.

현재 방향은 다음과 같다.

```text
필수 권한만 남긴다.
불필요한 재주입 권한보다 manifest content script와 사용자의 새로고침 안내를 우선한다.
```

릴리스 메모:

```text
스토어 리뷰와 유지보수를 위해 권한, 구조, 문구를 정리한 릴리스.
```

### 4.23 `0.5.5` 이후 닉네임 크기 안정화

- 기록 기준: 실사용 중 닉네임 크기가 같은 설정에서도 바뀌는 회귀 수정
- 버전 숫자: `0.5.5` 유지
  - 별도 수정 브랜치의 미릴리스 작업으로 유지하고, 실제 배포 시 다음 버전을 확정한다.
- 수정 이유:
  - 재스캔이 닉네임 앞쪽 prefix 주석을 지운 뒤 기존 생성 시간이 있다는 이유로 복원하지 않아, 닉네임이 채팅 크기 또는 브라우저 버튼 기본 크기를 상속할 수 있었다.
  - 닉네임 별도 크기 규칙이 일반 `font-size: inherit !important` 규칙보다 약해 CHZZK의 행 DOM 형태에 따라 계산 크기가 달라졌다.
  - 팝업과 미니/게스트 채팅이 같은 전체 옵션 객체를 독립 저장해, 미니 채팅 조작이 방금 바꾼 닉네임 설정을 오래된 값으로 되돌릴 수 있었다.

주요 변경:

- `content-chat-annotate.js`, `content.css`
  - 기존 생성 시간 또는 네이티브 시간이 있어도 닉네임 prefix를 매번 복원
  - 주석된 채팅 행의 닉네임 별도 크기 규칙을 일반 상속 규칙보다 명확히 우선 적용
- `background.js`, `content-options.js`, `content-mini-chat.js`, `content-guest-chat.js`, `content-runtime.js`, `popup.js`
  - 옵션 쓰기를 background의 단일 FIFO 큐로 모으고, 팝업과 미니/게스트 채팅은 자신이 바꾼 키만 patch 저장
  - 팝업 읽기도 FIFO 앞선 쓰기가 끝난 뒤 처리하고, 저장 후 content 직접 적용을 제거해 `storage.onChanged`를 단일 적용 경로로 사용
  - content의 쓰기 성공 응답 뒤에도 background FIFO read barrier로 최신 저장값을 다시 확인해, 늦은 과거 응답이 더 최신 storage 변경을 덮지 않게 처리
  - 쓰기 응답 타임아웃은 확정 실패로 간주하지 않고 read barrier로 저장 결과를 확인하며, 확인되지 않은 경우에도 새 storage 상태를 과거 snapshot으로 되돌리지 않음
  - 저장 변경 중인 미니 채팅 상태는 새 저장값 위에 미니 관련 patch만 다시 적용하고, 저장 실패 시에도 최신 외부 설정으로 복구
  - 미니 채팅 FIFO에서 완료된 patch는 즉시 optimistic overlay에서 제거하고 아직 대기 중인 patch만 다시 계산해, 후속 위치 저장 중 옛 배율이 살아나지 않게 처리
  - 미니 채팅 버블 복원의 저장/재조회가 모두 타임아웃된 경우는 확정 실패가 아니므로 화면을 다시 버블로 되돌리지 않고, 늦은 storage 결과에 맡기도록 처리
  - 새 storage 변경 뒤 늦게 끝난 프레임 초기 읽기가 최신 옵션을 덮지 않도록 세대와 상태 revision을 확인
- `popup.js`, `popup.css`
  - 팝업 미리보기에서도 닉네임 별도 크기를 실제 채팅과 동일하게 표시
- `tests/extension-regressions.test.cjs`, `tools/verify-live-edge.cjs`, `tools/validate-extension.mjs`
  - 늦은 배지 추가와 재스캔 뒤에도 닉네임 크기/prefix가 유지되는지 자동 검증
  - 팝업 닉네임 설정 직후 미니 배율을 바꿔도 새 설정과 미니 배율이 함께 보존되는지 검증
  - 게스트 채팅 쓰기 응답이 타임아웃보다 늦는 순서, 게스트 READ snapshot 뒤 최신 storage 이벤트가 먼저 도착하는 순서, `미니 저장 이벤트 → 외부 최신 설정 → 늦은 미니 성공 응답` 순서를 자동 재현해 저장값과 화면이 일치하는지 검증
  - `배율 patch 완료 → 외부 배율 변경 → 위치 patch 대기` 순서에서 완료된 배율이 다시 적용되지 않는지 검증
  - 미니 버블 복원 저장이 두 번의 타임아웃 뒤 늦게 성공하는 순서에서도 복원된 패널이 다시 최소화되지 않는지 검증
  - 실제 `background.js`를 격리 실행해 미니 patch 뒤 팝업 patch의 FIFO 병합과 저장 실패 복구를 검증
  - 라이브 검증을 닉네임 크기 최댓값 한 건이 아니라 모든 표본의 주석 누락·최소·최대·편차 계약으로 강화
  - 채팅 박스 좌우 여백 검증은 여러 줄 메시지의 range 경계로 인한 오탐을 피하도록 한 줄 표본만 사용

### 4.25 `0.6.1` 나만 보는 채팅 전환 및 안정화 릴리즈

- 기록 기준: `0.5.6` 이후 비로그인 읽기 전용 모드를 실제 전송 없는 로컬 반응 기능으로 확장하고 안정화한 변경의 배포 승격
- 버전 숫자: `0.6.1`
- 수정 이유:
  - 기존 비로그인 채팅은 실제 채팅을 볼 수 있지만 로그인 안내 입력 영역에서는 아무 동작도 할 수 없었다.
  - 방송을 보며 짧은 반응을 남기되 스트리머나 다른 시청자에게 보내고 싶지 않은 사용 흐름을 로컬 표시 원칙 안에서 지원할 필요가 있었다.

주요 변경:

- 사용자 노출 명칭을 `비로그인 채팅`에서 `나만 보는 채팅`으로 변경
- credentialless guest iframe과 다른 사람의 실시간 채팅 흐름은 그대로 유지
- 나만 보는 입력 차단은 부모 iframe의 `credentialless` 속성·프로퍼티뿐 아니라 브라우저의 `document.hasStorageAccess()`가 `false`인지 확인된 뒤에만 활성화
- 위 격리 검증 API가 없거나 결과가 다르면 원본 입력을 숨기거나 이벤트를 가로채지 않는 실패 시 닫힘 방식으로 처리
- 초기 구현에서는 별도 로컬 입력 iframe과 하단 패널을 붙였으나, 사용자가 원한 동작은 원래 입력창과 채팅 목록을 그대로 쓰는 방식이어서 릴리스 전에 폐기
- 치지직이 소유한 로그인 안내 입력과 전송 버튼은 숨김·비활성 상태로 보존하고, 동일한 클래스·크기·스타일을 복제한 확장 소유 입력과 버튼을 같은 자리에 배치
- 복제 입력은 치지직 이벤트 리스너와 연결하지 않고 `keydown`, `beforeinput`, 전송 버튼 `click`, 폼 `submit`을 캡처 단계에서 모두 로컬 처리
- 원본 DOM에 인라인 `on*` 이벤트 속성이 생기는 경우까지 대비해 복제 입력과 버튼에서는 실행 속성을 제거
- 빈 입력 안내는 `나만 보는 채팅, 실제로 전송되지 않음`으로 줄이고 안내가 보일 때만 세로 스크롤을 숨겨 한 줄로 표시
- 입력한 메시지는 마지막 실제 채팅 행의 외형을 안전하게 복제해 같은 `[role="log"]` 흐름에 삽입
- 로컬 메시지는 전송 뒤 도착한 실제 채팅 수를 시간순 위치 정보로 유지하며, 이후 실제 채팅이 오면 일반 채팅과 함께 위로 밀려남
- 치지직이 기존 행 DOM을 재활용하는 경우에도 네이티브 행의 닉네임·본문 지문 변화를 비교해 새 원격 메시지 수를 계산하고 그만큼 로컬 행을 오래된 위치로 이동
- 로컬 전송 당시 실제 채팅이 비어 있었다면 첫 수신 행부터 새 채팅으로 계산하고, 서로 겹치지 않는 과거 가상 목록이나 일시적인 빈 목록은 판정 불가로 두어 로컬 행을 최신 위치에 재배치하지 않음
- 초기 한글 IME 보호에서 `compositionend` 뒤 300ms 동안 다음 Enter까지 막아 전송에 Enter가 두 번 필요하던 문제를 수정
- 시간 기준 차단 대신 조합 중 Enter만 전송 예약으로 기록하고, 마지막 조합 문자가 입력된 `compositionend`에서 로컬 메시지를 정확히 한 번 추가한 뒤 같은 키의 후행 이벤트만 `keyup`까지 차단
- 조합 종료만 발생한 경우에는 전송하지 않으며, `focusout`, 창 포커스 이탈, 로컬 입력 DOM 교체 시 남은 조합 상태를 초기화해 다음 Enter가 막히지 않게 처리
- 과거 가상 목록에서 새로 작성한 로컬 메시지는 해당 목록의 보조 시간축을 따로 추적해 그 상태에서 새 실제 행이 들어와도 같은 방식으로 위로 밀려남
- 사이트 렌더링이 로컬 행을 제거해도 기록된 실제 채팅 수에 맞는 원래 시간순 위치로 복구하고, 현재 가상 목록이 기존 타임라인과 겹치지 않으면 최신 위치에 다시 붙이지 않음
- 로컬 행은 닉네임을 `나`로 표시하고, 메시지는 `textContent`로만 기록하며, 복제된 링크·미디어·폼 속성·인라인 이벤트를 제거
- 닉네임, 타임스탬프, 채팅 박스, 굵기, 글자색과 글자 크기 표시 설정을 실제 채팅 행과 같은 주석 경로로 반영
- 로컬 메시지는 메모리에만 최대 100개 유지하며, 제한 정리 시 실제 수신 행은 삭제하지 않음
- 반복 입력 뒤 탭이 멈추던 문제는 서로 다른 시점의 로컬 행들이 고정 크기 가상 목록 밖에서 같은 오래된 끝자리를 번갈아 차지하고, 그 이동을 `MutationObserver`가 다시 동기화하던 피드백 루프로 확인
- 현재 네이티브 목록 길이로 보정한 유효 시간 슬롯이 같은 로컬 행을 하나의 상대 배치 체인으로 묶고, 일반·과거 가상 목록의 끝자리 DOM 쓰기를 모두 멱등화해 행 왕복 이동을 제거
- 연결된 로컬 행의 단순 이동은 삭제 복구로 판단하지 않고, Observer의 즉시 타임라인 처리는 실제 네이티브 행 변화에만 적용해 확장 자체 mutation의 재진입을 차단

영향받는 사용자 경험:

- 다른 사람의 실제 채팅을 로그인 없이 계속 읽으면서 원래 입력창 모양으로 내 화면에만 보이는 반응을 남길 수 있다.
- 내가 보낸 로컬 메시지는 다른 사람의 채팅과 같은 목록에 시간순으로 나타나지만 스트리머와 다른 시청자에게는 전송되지 않는다.
- 입력 내용은 치지직이 소유한 원본 입력 DOM과 전송 리스너에 들어가지 않으며 나만 보는 채팅창을 끄거나 전체화면으로 전환하거나 새로고침하면 사라진다.
- 헤더 버튼, 팝업, README의 명칭과 설명이 `나만 보는 채팅` 기준으로 일치한다.

검증 기준:

  - 스타일 프리셋을 바꾸면 사용자가 이미 선택한 기본·나만 보기·미니 채팅창 모드가 기본값 또는 나만의 프리셋 저장 당시 값으로 바뀌었다.
  - 나만의 프리셋 저장 버튼도 채팅창 설정을 함께 보관해, 외형을 다시 불러오는 동작이 채팅 사용 방식까지 바꾸는 문제가 있었다.
  - 나만 보기 전환 버튼이 채팅 헤더에 있어 실제 입력·전송 흐름과 떨어져 있었고 헤더 아이콘 영역도 불필요하게 복잡했다.

주요 변경:

- 프리셋 전용 스냅샷에서 `useGuestChatFrame`, `useMiniFloatingChat`, `miniFloatingChatFullscreenOnly`를 제외
- 기본·깔끔·미니멀 프리셋 적용 시 현재 채팅창 모드와 미니 채팅 전체화면 전용 설정을 별도로 보존
- 나만의 프리셋 저장 결과에 채팅창 설정 세 값이 들어가지 않도록 변경
- 나만의 프리셋을 불러올 때도 현재 채팅창 설정을 유지하고 저장된 외형·표시 설정만 적용
- `0.6.1`에서 저장한 나만의 프리셋에 채팅창 값이 남아 있어도 로딩 단계에서 제거해 현재 선택을 덮어쓰지 않도록 호환 처리
- 프리셋 활성 상태 판정에서도 채팅창 설정을 제외해, 모드만 바꿔도 선택된 프리셋 표시가 사라지지 않도록 변경
- 실제 `popup.html`과 `popup.js`를 Edge에서 실행하는 팝업 회귀 하네스를 추가해 저장소 값과 라디오 UI를 함께 검증
- 나만 보기 전환 버튼을 헤더에서 제거하고 하단 `채팅` 전송 버튼 바로 왼쪽으로 이동
- 기본 채팅에서는 최상위 페이지의 원본 전송 버튼 앞에, 나만 보는 채팅에서는 credentialless iframe의 로컬 전송 버튼 앞에 각각 렌더링
- 설정·미니 채팅 버튼은 기존 헤더 위치를 유지하고, 미니 채팅 iframe과 격리 검증에 실패한 guest iframe에는 나만 보기 버튼을 만들지 않음
- 하단 버튼을 `type="button"`으로 유지해 폼 submit과 치지직 전송 버튼 클릭 경로에 들어가지 않도록 보존

영향받는 사용자 경험:

- 기본·나만 보기·미니 중 하나를 선택한 뒤 어떤 스타일 프리셋을 눌러도 채팅창 선택이 유지된다.
- 나만의 프리셋을 저장하거나 불러와도 채팅창 모드와 전체화면 전용 설정이 바뀌지 않는다.
- 이전 버전에서 저장한 나만의 프리셋도 현재 채팅창 선택을 안전하게 유지한다.
- 나만 보기 전환 버튼이 실제 채팅 전송 버튼 옆에 있어 입력 흐름에서 바로 켜고 끌 수 있으며, 헤더에는 설정·미니 버튼만 남는다.

검증 기준:

- 세 채팅창 모드와 기본·깔끔·미니멀 프리셋의 9개 조합에서 선택 및 전체화면 전용 설정 보존 확인
- 나만의 프리셋 저장 객체에 채팅창 설정 세 키가 없는지 확인
- 채팅창 설정만 바꾼 뒤에도 나만의 프리셋 활성 표시가 유지되는지 확인

- credentialless 나만 보기 iframe에서 `나만 보기 버튼 → 로컬 전송 버튼 → 숨긴 원본 전송 버튼` 순서와 단일 인스턴스 유지 확인
- 미니 iframe·비신뢰 guest iframe에서 나만 보기 버튼이 생성되지 않고, 버튼 클릭이 사이트 submit·전송 클릭을 발생시키지 않는지 확인

## 6. 현재 중요한 구현 결정

### 6.1 설정은 팝업에서 고르고 content script가 적용한다

팝업은 사용자가 고르는 화면이고, content script는 치지직 페이지 안에서 실제 표시를 바꾸는 실행부다.

이 구분이 중요한 이유는 브라우저 확장에서는 팝업과 웹페이지가 같은 실행 공간이 아니기 때문이다. 팝업에서 체크박스를 눌렀다고 웹페이지 DOM이 바로 바뀌는 것이 아니라, 저장소와 메시지를 통해 content script가 받아 적용한다.

### 6.2 CSS와 dataset 중심으로 숨긴다

이 프로젝트는 실제 채팅 데이터를 삭제하지 않는다. 가능한 한 요소를 삭제하기보다 class, dataset, CSS 변수로 보이는 상태만 조정한다.

### 6.3 나만 보는 채팅은 실제로 전송하지 않는다

나만 보는 채팅창은 credentialless iframe으로 실제 채팅을 그대로 보여 준다. 부모 iframe의 `credentialless` 표시와 브라우저의 실제 저장소 접근 차단 상태가 모두 확인된 뒤에만 치지직이 소유한 원본 입력과 전송 버튼을 숨김·비활성 상태로 보존하고, 같은 외형의 확장 소유 입력과 버튼을 사용자에게 보여 준다. 나만 보기 전환 버튼은 기본 채팅의 원본 전송 버튼과 나만 보는 채팅의 로컬 전송 버튼 바로 왼쪽에 표시하되, 미니 iframe이나 격리 검증에 실패한 iframe에는 만들지 않는다. Enter, `beforeinput`, 클릭, submit은 캡처 단계에서 소비하며 메시지는 같은 채팅 목록에 로컬 행으로만 추가한다. 격리 상태가 확인되지 않으면 로컬 입력 기능 자체를 켜지 않으며, 차단기가 실패하더라도 credentialless 프레임에는 사용자 로그인 자격 증명이 없다는 두 번째 안전벽이 있다. 스트리머와 다른 시청자에게는 보이지 않으며 실제 수신 채팅 행은 수정하거나 삭제하지 않는다.

### 6.4 미니 플로팅 채팅은 원래 채팅창과 충돌하지 않아야 한다

미니 플로팅 채팅창은 보조 화면이다. 특히 나만 보는 채팅과 동시에 켜졌을 때 충돌하지 않게 숨김 조건과 모드 전환을 관리한다.

### 6.5 자동 대비 보정은 명시적으로 켠 경우에만 적용한다

`0.5.4` 후속 패치의 핵심은 자동 색 보정이 사용자의 의도보다 많이 개입하지 않게 하는 것이었다.

현재 기준:

- 사용자가 `글자색 자동 보정`을 켠 경우에만 보정한다.
- 자동 보정이 꺼져 있으면 사용자가 고른 색을 최대한 그대로 둔다.
- 닉네임 색 메시지도 불필요하게 바꾸지 않는다.

### 6.6 확장 권한은 최소화한다

`0.4.1`에서 권한을 크게 줄인 뒤, 현재 제품 방향은 "필요한 권한만 남긴다"로 정리됐다.

현재 manifest 기준:

```text
permissions:
- storage

host_permissions:
- https://chzzk.naver.com/*
```

이 결정의 이유는 두 가지다.

- 스토어 심사에서 과도한 권한으로 보이는 것을 줄인다.
- 이 확장이 "내 브라우저에서만 채팅 표시를 조정한다"는 제품 방향을 권한 구조에서도 보여준다.

따라서 앞으로 새 기능을 만들 때도 `activeTab`, `scripting`, `webNavigation`, 넓은 host permission을 다시 추가하기 전에 먼저 다른 구현 방법을 검토한다. 정말 필요하다면 `project-after-direction.md`에 왜 필요한지, 어떤 대안이 있었는지, 사용자에게 어떤 영향을 주는지 같이 기록한다.

현재 `0.7.0` 릴리즈는 프로젝트 디렉션의 핵심 방향인 "치지직 채팅창을 내 브라우저 화면에서만 읽기 쉽게 정리하고, 실제 전송 없이 나만의 반응을 남기는 도구"를 유지하면서 브라우저 로컬 오디오 압축 기능까지 제공한다.

버전 흐름을 크게 나누면 다음과 같다.

```text
0.1.x
-> 기본 표시 토글과 스타일 조정 시작

0.2.x
-> 비로그인 채팅과 헤더 버튼 실험

0.3.x
-> 미니 플로팅 채팅, 글자 크기, 비채팅 패널 제어 확장

0.4.x
-> 모듈화, 스토어 친화 정리, 글자색/닉네임색 옵션 추가

0.5.x
-> 미리보기 중심 팝업 재설계, 프리셋, 자동 대비 보정

0.6.x
-> 나만 보는 채팅 전환, 실제 미전송 안전벽, 타임라인·반복 입력·한글 IME 안정화
```

따라서 현재 이후의 개발은 새 기능을 많이 늘리는 것보다, 설정이 실제 채팅창에 안정적으로 반영되고 CHZZK DOM 변경에도 견디는 쪽을 우선해야 한다.
