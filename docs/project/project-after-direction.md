## 1. 이 문서의 역할

`project-direction.md`가 "무엇을 만들 것인가"를 정리한 문서라면, 이 문서는 "실제로 어떤 버전에서 무엇이 구현됐는가"를 기록하는 문서다.

쉽게 말하면 다음처럼 나뉜다.

```text
project-direction.md
-> 제품 의도, 기능 범위, 구현 원칙

project-after-direction.md
-> 현재 구현 상태, 버전별 패치, 실제 파일 구조, 유지보수 기준
```

이 문서는 단순한 changelog가 아니다. 버전마다 어떤 기능이 들어갔고, 그 변경이 제품 방향과 어떻게 연결되는지 같이 기록한다.

## 2. 현재 구현 요약

현재 빌드는 `치지직 채팅 커스텀`이라는 이름으로 동작한다.

사용자는 확장 팝업에서 채팅 미리보기를 보면서 표시 항목, 글자 크기, 색상, 자동 대비 보정, 채팅창 모드, 헤더 버튼 표시 여부를 조정할 수 있다. 설정은 저장되고, 치지직 페이지의 content script가 이를 읽어 사용자의 브라우저 화면에만 반영한다.

현재 사용자에게 보이는 핵심 기능은 다음이다.

- 닉네임, 배지, 타임스탬프 표시 토글
- 채팅 외 패널 표시 토글
- 채팅 박스 색상
- 글씨 크기와 닉네임 크기 조정
- 굵게
- 글자 색상 변경
- 닉네임 색상으로 채팅 표시
- 글자색 자동 보정
- 비로그인 읽기 전용 채팅창
- 미니 플로팅 채팅창
- 채팅 헤더의 설정/비로그인/미니 채팅 버튼
- 스타일 프리셋과 나만의 프리셋 저장

현재 확장이 하지 않는 일도 명확하다.

- 실제 채팅 메시지를 바꾸지 않는다.
- 채팅 전송을 대신하지 않는다.
- 삭제, 차단, 신고, moderation 기능을 제공하지 않는다.
- 치지직 서버 상태나 방송 송출에 영향을 주지 않는다.

## 3. 프로젝트 디렉션 반영 맵

| 프로젝트 디렉션 항목 | 현재 구현 상태 | 실제 표현 방식 | 주요 파일 |
|---|---|---|---|
| 로컬 표시 제어 | 완료 | `storage`에 저장된 옵션을 content script가 페이지에 적용 | `background.js`, `content-options.js`, `content-runtime.js` |
| 닉네임/배지/시간 토글 | 완료 | 채팅 행을 분석해 각 요소 표시를 독립 제어 | `content-chat-annotate.js`, `content.css`, `popup.html` |
| 채팅 외 패널 숨김 | 완료 | 랭킹, 승부예측 등 비채팅 패널을 옵션으로 숨김 | `content-core.js`, `content.css`, `popup.js` |
| 채팅 박스/글자 스타일 | 완료 | CSS 변수와 dataset으로 색상, 크기, 굵기 적용 | `content-core.js`, `content-theme.js`, `content.css` |
| 글자색 자동 보정 | 완료 | 사용자가 자동 보정을 켠 경우에만 대비 보정 적용 | `content-chat-annotate.js`, `content-options.js`, `popup.js` |
| 비로그인 채팅창 | 완료 | 읽기 전용 guest iframe으로 전환 | `content-guest-chat.js`, `background.js` |
| 미니 플로팅 채팅창 | 완료 | 드래그, 리사이즈, 입력 전용, 전체화면 전용, 최소화 지원 | `content-mini-chat.js`, `content.css` |
| 헤더 버튼 | 완료 | 채팅 헤더에 설정, 비로그인, 미니 채팅 버튼 추가 | `content-guest-chat.js`, `popup.html` |
| 미리보기 중심 팝업 | 완료 | 팝업 첫 화면에 채팅 미리보기와 프리셋 배치 | `popup.html`, `popup.css`, `popup.js` |
| 버전 동기화 | 완료 | manifest/package/popup/content-bootstrap 버전 동기화 | `manifest.json`, `package.json`, `package-lock.json`, `popup.js`, `content-bootstrap.js` |

## 4. 버전별 패치 기록

이 저장소에는 별도 Git tag가 없다. 따라서 버전 기록은 `git log`와 `manifest.json`, `package.json`, `popup.js`, `content-bootstrap.js`의 버전 값을 기준으로 정리한다.

  - 확장 권한을 심사 친화적으로 축소

기술 변경:

- `content.css` 분리
- 기존 큰 `content.js` 구조 정리 준비
- package/validator 구조 대폭 정리
- `activeTab`, `scripting`, `webNavigation` 권한 제거

권한 변경 배경:

초기 버전에서는 실제 치지직 페이지와 subframe 대응, stale content script 재주입, navigation 대응을 위해 권한이 점점 늘어났다.

- `0.1.0`: `storage`, `activeTab`
- `0.1.1`: `scripting` 추가
- `0.1.14`: `webNavigation` 추가
- subframe 대응 과정에서 `https://*.chzzk.naver.com/*` host permission 사용

하지만 스토어 심사 관점에서는 권한이 많을수록 심사가 늦어지거나 설명 부담이 커질 수 있다. `0.4.1`에서는 이 문제를 줄이기 위해 직접 주입과 navigation 재주입 흐름을 제거하고, manifest content script 중심으로 단순화했다.

현재 방향은 다음과 같다.

```text
필수 권한만 남긴다.
불필요한 재주입 권한보다 manifest content script와 사용자의 새로고침 안내를 우선한다.
```

릴리스 메모:

```text
스토어 리뷰와 유지보수를 위해 권한, 구조, 문구를 정리한 릴리스.
```

## 6. 현재 중요한 구현 결정

### 6.1 설정은 팝업에서 고르고 content script가 적용한다

팝업은 사용자가 고르는 화면이고, content script는 치지직 페이지 안에서 실제 표시를 바꾸는 실행부다.

이 구분이 중요한 이유는 브라우저 확장에서는 팝업과 웹페이지가 같은 실행 공간이 아니기 때문이다. 팝업에서 체크박스를 눌렀다고 웹페이지 DOM이 바로 바뀌는 것이 아니라, 저장소와 메시지를 통해 content script가 받아 적용한다.

### 6.2 CSS와 dataset 중심으로 숨긴다

이 프로젝트는 실제 채팅 데이터를 삭제하지 않는다. 가능한 한 요소를 삭제하기보다 class, dataset, CSS 변수로 보이는 상태만 조정한다.

### 6.3 비로그인 채팅은 읽기 전용이다

비로그인 채팅창은 보는 용도다. 채팅 전송까지 지원하면 제품 범위가 커지고, 원래 치지직 채팅 동작을 바꾸는 쪽에 가까워진다. 그래서 현재 방향에서는 읽기 전용으로 제한한다.

### 6.4 미니 플로팅 채팅은 원래 채팅창과 충돌하지 않아야 한다

미니 플로팅 채팅창은 보조 화면이다. 특히 비로그인 채팅과 동시에 켜졌을 때 충돌하지 않게 숨김 조건과 모드 전환을 관리한다.

### 6.5 자동 대비 보정은 명시적으로 켠 경우에만 적용한다

`0.5.4` 후속 패치의 핵심은 자동 색 보정이 사용자의 의도보다 많이 개입하지 않게 하는 것이었다.

현재 기준:

- 사용자가 `글자색 자동 보정`을 켠 경우에만 보정한다.
- 자동 보정이 꺼져 있으면 사용자가 고른 색을 최대한 그대로 둔다.
- 닉네임 색 메시지도 불필요하게 바꾸지 않는다.

### 6.6 확장 권한은 최소화한다

`0.4.1`에서 권한을 크게 줄인 뒤, 현재 제품 방향은 "필요한 권한만 남긴다"로 정리됐다.

현재 manifest 기준:

```text
permissions:
- storage

host_permissions:
- https://chzzk.naver.com/*
```

이 결정의 이유는 두 가지다.

- 스토어 심사에서 과도한 권한으로 보이는 것을 줄인다.
- 이 확장이 "내 브라우저에서만 채팅 표시를 조정한다"는 제품 방향을 권한 구조에서도 보여준다.

따라서 앞으로 새 기능을 만들 때도 `activeTab`, `scripting`, `webNavigation`, 넓은 host permission을 다시 추가하기 전에 먼저 다른 구현 방법을 검토한다. 정말 필요하다면 `project-after-direction.md`에 왜 필요한지, 어떤 대안이 있었는지, 사용자에게 어떤 영향을 주는지 같이 기록한다.

0.1.x

0.2.x
-> 비로그인 채팅과 헤더 버튼 실험

0.3.x

0.4.x
-> 모듈화, 스토어 친화 정리, 글자색/닉네임색 옵션 추가
