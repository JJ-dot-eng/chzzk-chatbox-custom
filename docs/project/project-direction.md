## 1. 이 문서의 역할

이 문서는 이 프로젝트가 어떤 방향의 제품인지 정리하는 기준 문서다.

쉽게 말하면, 앞으로 기능을 추가하거나 고칠 때 다음 질문에 답하기 위한 문서다.

```text
이 기능이 치지직 채팅 커스텀의 방향과 맞는가?
사용자 화면에서만 바뀌는가?
채팅 서버나 실제 채팅 데이터에는 영향을 주지 않는가?
```

`project-after-direction.md`는 이 문서의 방향이 실제 버전별 패치에서 어떻게 구현됐는지 기록한다.

## 2. 최종 제품 정의

**치지직 채팅 커스텀은 치지직 채팅창의 표시 항목, 글자 크기, 색상, 채팅 외 패널, 나만 보는 채팅창과 미니 채팅창을 사용자의 브라우저 화면에서만 조정하는 MV3 브라우저 확장 프로그램이다.**

핵심은 서버 기능을 바꾸는 것이 아니라, 사용자가 보는 채팅 화면을 더 읽기 쉽고 편하게 만드는 것이다.

## 3. 한 줄 컨셉

## 4. 제품 원칙

### 4.1 로컬 표시 제어만 한다

이 확장은 사용자가 보는 화면만 바꾼다.

하지 않는 것:

- 방송 송출 변경
- 치지직 서버 상태 변경
- 실제 채팅 메시지 삭제 또는 수정
- 사용자 계정 조작
- 차단, 삭제, moderation 같은 운영 기능

### 4.2 채팅 읽기 경험을 우선한다

기능의 목적은 채팅을 보기 쉽게 만들고, 실제 전송 없이 내 화면에서만 반응을 남길 수 있게 하는 것이다.

좋은 방향:

```text
닉네임과 배지를 숨겨 채팅 내용을 더 넓게 본다.
글자 크기를 키워 멀리서도 읽는다.
채팅 박스와 글자색 대비를 맞춰 가독성을 높인다.
실제 전송 없이 내 화면에만 메시지를 추가한다.
```

나쁜 방향:

```text
치지직 서버로 채팅 전송을 대신한다.
채팅 내용을 자동으로 수정한다.
다른 사람에게 보이는 채팅 상태를 바꾼다.
```

### 4.3 설정은 빠르게 접근 가능해야 한다

사용자는 방송을 보는 중에 설정을 바꾼다. 따라서 설정은 복잡한 메뉴보다 빠른 토글, 프리셋, 미리보기 중심이어야 한다.

현재 방향:

- 팝업 첫 화면에서 미리보기 제공
- 스타일 프리셋 제공
- 빠른 조절 토글 제공
- 세부 설정은 보이기, 스타일, 채팅창, 버튼으로 분리
- 스타일 프리셋과 나만의 프리셋은 채팅창 모드 및 전체화면 전용 설정과 독립적으로 동작

### 4.4 CHZZK DOM 변경에 견딜 수 있어야 한다

치지직 화면 구조는 언제든 바뀔 수 있다. 그래서 selector는 너무 좁게 잡지 않고, 실패하면 조용히 무시하거나 다음 스캔에서 복구할 수 있어야 한다.

중요한 기준:

- 채팅 행인지 충분히 확인한 뒤 적용한다.
- 닉네임, 배지, 타임스탬프, 메시지 영역을 독립적으로 판단한다.
- DOM 변경으로 일부 요소를 못 찾더라도 전체 페이지를 깨뜨리지 않는다.

### 4.5 개인정보와 권한은 작게 유지한다

확장은 `storage` 권한과 `https://chzzk.naver.com/*` 범위에서 동작한다.

방향:

- 설정값은 브라우저 저장소에만 저장한다.
- 불필요한 외부 서버 저장을 하지 않는다.
- 치지직 전체 사이트 밖으로 기능 범위를 넓히지 않는다.

## 5. 타깃 사용자

### 5.1 1차 타깃

치지직 방송을 보면서 채팅창을 자주 읽는 사용자.

주요 상황:

- 채팅이 너무 복잡해서 닉네임, 배지, 시간 표시를 줄이고 싶다.
- 글자가 작아 멀리서 보기 어렵다.
- 채팅 박스나 글자색을 내 눈에 맞게 바꾸고 싶다.
- 후원 랭킹, 승부예측, 스포츠 정보 같은 비채팅 패널을 숨기고 싶다.
- 전체화면이나 다른 화면 구성에서 작은 채팅창을 띄우고 싶다.

### 5.2 2차 타깃

실제 채팅은 읽되 작성한 메시지는 다른 사람에게 보내지 않고 내 화면에서만 보고 싶은 사용자, 또는 미니 플로팅 채팅창을 보조 화면처럼 쓰고 싶은 사용자.

## 6. 핵심 기능 범위

### 6.1 표시 옵션

| 기능 | 방향 |
|---|---|
| 닉네임 표시 | 채팅 옆 이름을 켜고 끈다. |
| 배지 표시 | 구독, 팬 배지 표시를 켜고 끈다. |
| 타임스탬프 표시 | 메시지 시간 표시를 켜고 끈다. |
| 채팅 외 패널 표시 | 랭킹, 승부예측 등 비채팅 패널을 숨길 수 있게 한다. |
| 빠른 버튼 표시 | 설정·미니 채팅 버튼은 헤더에, 나만 보기 전환 버튼은 하단 전송 버튼 왼쪽에 표시하며 필요할 때만 보이게 한다. |

### 6.2 외형 옵션

| 기능 | 방향 |
|---|---|
| 채팅 박스 | 메시지 배경 박스를 켜고 색상을 조정한다. |
| 글씨 크기 | 채팅 글자와 이모티콘 크기를 조정한다. |
| 닉네임 크기 | 채팅 내용과 별도로 닉네임 크기를 조정한다. |
| 굵게 | 채팅 텍스트를 더 또렷하게 만든다. |
| 글자 색상 | 채팅 텍스트 색상을 바꾼다. |
| 닉네임 색 채팅 | 채팅 내용을 닉네임 색으로 표시한다. |
| 글자색 자동 보정 | 배경과 글자색이 너무 비슷할 때 읽기 쉬운 쪽으로 보정한다. |

### 6.3 채팅창 모드

| 모드 | 방향 |
|---|---|
| 기본 채팅 | 치지직 원래 채팅창을 유지한다. |
| 나만 보는 채팅 | 실제 채팅을 로그인 없이 그대로 표시하고, 원래 입력창 외형으로 작성한 메시지는 같은 채팅 목록에만 로컬 행으로 추가한다. 치지직에는 전송하지 않는다. |
| 미니 플로팅 | 페이지 안에 작은 채팅창을 띄운다. 드래그, 크기 조절, 입력 전용, 전체화면 전용 표시를 지원한다. |

## 7. MVP와 확장 범위

### 7.1 제품의 기본 완성 기준

이 프로젝트의 기본 완성 기준은 다음이다.

- 닉네임, 배지, 타임스탬프가 각각 독립적으로 켜지고 꺼진다.
- 채팅 외 패널을 숨겨도 실제 채팅 메시지는 남는다.
- 글자 크기, 채팅 박스, 글자색 변경이 저장되고 새로고침 후에도 유지된다.
- 나만 보는 채팅은 다른 사람의 실시간 채팅과 원래 입력창 외형을 훼손하지 않는다.
- 나만 보는 채팅의 Enter, 전송 버튼, submit 우회 경로는 모두 실제 전송 없이 같은 채팅 목록의 로컬 행만 만든다.
- 나만 보는 채팅의 로컬 행은 일반 채팅과 같은 시간순 흐름에 참여해 새 실제 채팅이 오면 위로 밀려나고 화면 밖으로 자연스럽게 묻힌다.
- 나만 보는 채팅의 로컬 입력은 브라우저가 credentialless 저장소 격리를 실제로 적용한 프레임에서만 활성화하며, 확인할 수 없으면 원본 입력과 이벤트를 그대로 둔다.
- 나만 보는 채팅의 로컬 행에도 닉네임, 시간, 채팅 박스, 굵기, 글자색과 글자 크기 설정이 실제 채팅과 같은 방식으로 적용된다.
- 미니 플로팅 채팅창은 기본 채팅창과 충돌하지 않는다.
- 설정 팝업과 실제 채팅창 적용 상태가 서로 어긋나지 않는다.

### 7.2 확장 가능 기능

추후 고려할 수 있는 기능:

- 더 많은 프리셋
- 설정 내보내기/가져오기
- 특정 방송별 설정 저장
- 접근성 중심 고대비 프리셋
- selector 변경 감지용 진단 화면

### 7.3 제외할 기능

다음 기능은 제품 방향과 맞지 않는다.

- 치지직 서버로 채팅을 자동 또는 대신 전송하는 기능
- 채팅 삭제, 차단, 신고, moderation 조작
- 방송 송출 제어
- 치지직 서버 API를 통한 데이터 변경
- 다른 사용자에게 영향을 주는 기능

현재 제품의 사용 흐름은 다음을 기준으로 한다.

```text
확장 팝업
  - 미리보기
  - 스타일 프리셋
  - 빠른 조절
  - 세부 설정
    - 보이기: 닉네임, 배지, 타임스탬프, 채팅 외 패널

    - 채팅창: 기본, 나만 보는 채팅, 미니 플로팅
    - 버튼: 헤더·하단 빠른 버튼 표시 여부

치지직 페이지
  - 원래 채팅창
  - 헤더 버튼: 설정, 미니 채팅
  - 하단 전송 버튼 왼쪽: 나만 보기 전환

    - 원래 입력창과 동일한 외형의 로컬 입력
    - 로컬 전송 버튼 왼쪽의 나만 보기 전환
    - 실제 채팅 목록 안의 로컬 메시지 행
  - 미니 플로팅 채팅창
```

## 9. 구현 원칙

### 9.1 저장

사용자 설정은 Chrome extension storage에 저장한다.

나만 보는 채팅에서 작성한 메시지는 어떤 저장소에도 보관하지 않는다. 나만 보는 채팅창을 끄거나 전체화면으로 전환하거나 페이지를 새로고침하면 즉시 사라진다.

버전이 올라가도 이전 설정을 최대한 유지해야 한다. 새 옵션이 추가되면 기본값을 안전하게 둔다.

### 9.2 적용

옵션 적용은 다음 방식이 우선이다.

1. 저장된 옵션을 읽는다.
2. content script가 페이지에 옵션 상태를 반영한다.
3. CSS class, dataset, CSS variable로 표시를 바꾼다.
4. MutationObserver와 주기적 스캔으로 새 채팅 행에도 적용한다.

### 9.3 실패 처리

치지직 DOM이 바뀌면 일부 selector가 실패할 수 있다. 이때 사용자가 보는 방송 페이지 자체가 망가지면 안 된다.

원칙:

- 찾지 못한 요소는 건너뛴다.
- 다음 MutationObserver 또는 스캔에서 다시 시도한다.
- validator와 실제 브라우저 확인으로 selector drift를 잡는다.

## 10. 버전 관리 원칙

이 프로젝트는 Chrome/Edge 확장 프로그램이라 버전 동기화가 중요하다.

버전을 올릴 때 확인할 파일:

- `manifest.json`
- `package.json`
- `package-lock.json`
- `popup.js`
- `content-bootstrap.js`

간단히 말해, 확장 프로그램이 새 버전이라고 인식하는 곳과 팝업/content script가 서로 같은 버전이라고 확인하는 곳을 같이 맞춰야 한다.

## 12. 최종 방향

이 프로젝트의 최종 방향은 다음 한 문장으로 정리한다.

```text
치지직 채팅창을 사용자의 브라우저 화면에서만 더 읽기 쉽게 정리하고, 실제 전송 없이 나만의 반응을 남길 수 있게 하는 로컬 커스텀 확장 프로그램.
```

새 기능은 이 문장과 맞을 때만 제품 핵심 기능으로 넣는다.
